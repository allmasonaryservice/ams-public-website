## RULE SET 1 — Lighthouse 98+ on Every Page (Mobile + Desktop)

Build to this standard from the first line of code. Retrofitting is 10× harder.

---

### E1-1. Fonts — Non-Blocking (Critical)

**Never** add a font `<link rel="stylesheet">` to `<head>` directly. It blocks FCP by 300–800ms on mobile.

Always use the three-line non-blocking pattern:

```html
<!-- Step 1: preload tells browser to fetch early, no blocking -->
<link rel="preload" as="style" href="FONT_URL" />
<!-- Step 2: load as print, swap to all on load — never blocks render -->
<link rel="stylesheet" href="FONT_URL" media="print" onload="this.media='all'" />
<!-- Step 3: fallback for JS-disabled browsers -->
<noscript><link rel="stylesheet" href="FONT_URL" /></noscript>
```

This pattern is already in `BaseLayout.astro` for Fraunces + Satoshi + Leaflet CSS. Copy it exactly for any new font or CSS CDN link.

- [ ] No new `<link rel="stylesheet">` added to `<head>` without the 3-line pattern
- [ ] `rel="preconnect"` added for any new font domain

---

### E1-2. Images — Explicit Dimensions (Critical for CLS)

Every `<img>` tag must have `width`, `height`, `loading`, and `decoding` attributes.

```html
<!-- Wrong — causes layout shift -->
<img src="/images/photo.jpg" alt="Brick repair" />

<!-- Correct -->
<img src="/images/photo.jpg" alt="Brick repair" loading="lazy" decoding="async" width="800" height="450" />
```

Rules:
- `width` + `height` = the display size aspect ratio. Aspect ratio matters, not pixel-perfect match.
- Hero / LCP image: use `loading="eager"` (not lazy) + `fetchpriority="high"` — never lazy-load the largest above-fold image.
- All other images: `loading="lazy"` + `decoding="async"`.
- If image is inside a fixed-height CSS container (`height: 480px`), still add `width` + `height` — the attributes prevent the initial shift before CSS applies.
- WebP format for all new images. No JPG/PNG unless there is no alternative.

- [ ] Every `<img>` has `width` + `height` attributes
- [ ] Hero/LCP image has `fetchpriority="high"` and is NOT lazy-loaded
- [ ] All below-fold images have `loading="lazy" decoding="async"`
- [ ] All new images are WebP

---

### E1-3. Third-Party Scripts — Never Render-Blocking

Any `<script src="...">` in `<head>` without `defer`/`async` blocks the entire page parse.

Rules:
- Never add a `<script src>` to `BaseLayout.astro` `<head>` without `defer` or `async`.
- For scripts needed after interaction (maps, chat widgets, etc.) — load via `IntersectionObserver` when the section enters viewport, same pattern as Leaflet in `ServiceAreasSection.astro`.
- For scripts needed after page load but not immediately (analytics, etc.) — load via `requestIdleCallback`.

```js
// Pattern: lazy load via IntersectionObserver
const observer = new IntersectionObserver((entries) => {
  if (entries[0].isIntersecting) {
    const script = document.createElement('script');
    script.src = 'https://...';
    document.head.appendChild(script);
    observer.disconnect();
  }
}, { rootMargin: '200px' });
observer.observe(document.getElementById('my-section'));
```

- [ ] No new `<script src>` in `<head>` without `defer` or `async`
- [ ] Heavy third-party scripts use IntersectionObserver or `requestIdleCallback`

### E1-4. Animations — GPU-Safe Only

Using `top`, `left`, `width`, `height`, `margin`, or `padding` in animations causes layout recalculation every frame — tanks INP and FCP on mobile.

Rules:
- Animate only `transform` and `opacity`. Nothing else.
- `will-change: transform` — set dynamically in JS just before animation starts, remove via `transitionend` or `animationend` after. Never set permanently in CSS on idle elements.
- `transform: translateZ(0)` on elements that need a compositor layer (e.g. fixed navbar) — set once in CSS, not before/after animation.

```css
/* Wrong */
.card:hover { margin-top: -4px; width: 105%; }

/* Correct */
.card { transition: transform 250ms ease; }
.card:hover { transform: translateY(-4px) scale(1.02); }
```

- [ ] No animation uses `top`, `left`, `margin`, `padding`, `width`, `height`
- [ ] `will-change` is set/cleared dynamically — never left on idle elements

---

### E1-5. Scroll & Resize Handlers — Passive

Any scroll or touch listener without `{ passive: true }` forces the browser to wait before scrolling — adds visible jank on mobile.

```js
// Wrong
window.addEventListener('scroll', handler);

// Correct
window.addEventListener('scroll', handler, { passive: true });
window.addEventListener('touchstart', handler, { passive: true });
```

- [ ] All scroll listeners use `{ passive: true }`
- [ ] All touch listeners use `{ passive: true }`
- [ ] Resize handlers are debounced (min 100ms) or use `ResizeObserver`

### E1-6. Tap Targets — Mobile ≥ 44px

Google Lighthouse mobile audit flags tap targets smaller than 44×44px.

- All buttons, links, form inputs: minimum `44px` height on mobile.
- Icon-only buttons: add `padding` to reach 44px, or set `min-width: 44px; min-height: 44px`.
- Links in dense text (footer, etc.): add `padding: 8px 0` so the tap area is large enough.

```css
.my-btn {
  min-height: 44px;
  padding: 0 20px;
  display: inline-flex;
  align-items: center;
}
```

- [ ] Every interactive element is ≥ 44px tall on mobile
- [ ] No overlapping tap targets

## RULE SET 2 — Zero JavaScript Chunks (No Unwanted Bundles)

Astro's bundler tries to bundle every `<script>` tag. When a script uses browser-only APIs or TypeScript casts, the bundler produces an **empty chunk** — a wasted HTTP request with 0 bytes of useful code, and a build warning.

---

### E2-1. The Core Rule — When to Use `is:inline`

Use `<script is:inline>` when your script does **any** of these:

| Condition | Use `is:inline` |
|---|---|
| Uses `document.getElementById` / `querySelector` | Yes |
| Uses `window.*` globals | Yes |
| Has TypeScript casts: `as HTMLInputElement`, `el!` | Yes |
| Uses `addEventListener` directly on DOM elements | Yes |
| Uses `window.__gsap` / `window.__ScrollTrigger` / `window.__lenis` | Yes |
| Has no `import` statements and does not export anything | Yes |

Use plain `<script>` (bundled) only when:
- The script uses Astro's `import` system to import `.ts` modules that exist in the project
- The script has no browser-only APIs at the top level
- You explicitly want Astro to tree-shake and bundle it

In this codebase: **all section scripts and all magnet tool scripts use `is:inline`**. Follow that pattern.

---

### E2-2. The Three-Question Test

Before writing any `<script>` tag in a `.astro` component, answer:

1. Does this script touch the DOM? (`getElementById`, `querySelector`, `addEventListener`) → `is:inline`
2. Does this script use TypeScript casts (`as`, `!`) → `is:inline`
3. Does this script use `window.__gsap` / `window.__ScrollTrigger` / `window.__lenis`? → `is:inline`

If any answer is yes → `<script is:inline>`. If all three are no → plain `<script>` is fine.

---

### E2-3. GSAP — One Import, In BaseLayout Only

GSAP, ScrollTrigger, and Lenis are imported **once** in `BaseLayout.astro` and exposed on `window`:

```js
window.__gsap = gsap;
window.__ScrollTrigger = ScrollTrigger;
window.__lenis = lenis;
```

In any section component that needs GSAP:

```html
<script is:inline>
  window.addEventListener('animations:ready', () => {
    const gsap = window.__gsap;
    const ScrollTrigger = window.__ScrollTrigger;
    // use gsap and ScrollTrigger here
  });
</script>
```

**Never** do this in a section component — it creates a second GSAP bundle (+27 KB):

```js
// Wrong
import { gsap } from 'gsap';
import { ScrollTrigger } from 'gsap/ScrollTrigger';
```

- [ ] GSAP/ScrollTrigger/Lenis never imported inside section components
- [ ] Section scripts that need GSAP listen for `animations:ready` event
- [ ] Section scripts access GSAP via `window.__gsap` / `window.__ScrollTrigger`

---

### E2-4. No Framework Components Unless Explicitly Required

React, Vue, Svelte each add 30–100 KB gzipped. This project is pure Astro + vanilla JS.

If a framework component is ever needed:
- Use `client:visible` (loads when section enters viewport) — never `client:load`
- Keep the island small — one interactive widget, not an entire section

- [ ] No React/Vue/Svelte added unless explicitly required
- [ ] If used, framework islands use `client:visible`

---

### E2-5. Chunk Size Limits

After every `npm run build`, check JS chunk output. Acceptable sizes (gzipped):

| Chunk type | Max gzipped | Action if over |
|---|---|---|
| GSAP + ScrollTrigger | 50 KB | Already at 45 KB — do not add more GSAP plugins |
| Lenis | 8 KB | Fine |
| Astro internals | 8 KB | Fine — do not touch |
| Any section script | 5 KB | Refactor or split |
| Any magnet tool script | 10 KB | Refactor if over |
| **Any empty chunk** | 0 KB | **Always a bug — fix immediately** |

If a new chunk appears after adding a section: check if a `<script>` is missing `is:inline`. That is the cause 95% of the time.

- [ ] `npm run build` run after every new component that contains a `<script>` tag
